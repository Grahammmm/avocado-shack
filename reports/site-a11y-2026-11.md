# Site accessibility audit (WCAG 2.2 AA, criteria other than contrast), November 2026

An audit of the published build for WCAG 2.2 AA 1.1.1, 1.3.1, 2.1.1, 2.4.3, 2.4.7, 2.4.11, 2.5.8 and 4.1.2. **This is a measurement, not a conformance claim**: it records what one headless Chromium and a keyboard did, and no site, template, CSS or JS file was changed. Contrast (1.4.3) is in `reports/site-contrast-2026-11.md`. Two findings and six observations are below; every other check in the eight criteria passed.

## How this was measured

- Command (no argument; it builds its own scratch copy and removes it): `PLAYWRIGHT_MODULE=<playwright> PLAYWRIGHT_BROWSERS_PATH=<browsers> node storefront-mockup/site-a11y-qa.cjs`. It runs `python3 hass/sitegen.py --publish <fresh folder outside the repo>`, then `--check-publish` on the same folder, serves it on `127.0.0.1` only and prints one JSON document. Exit 0 means: all 3 routes x 2 widths present, 0 non-loopback requests, 0 non-GET requests, and the detector controls below behaved.
- Routes and widths: `/`, `/hike/`, `/404.html` at 390x844 and 1440x900 (reduced motion, Pacific time zone, clock fixed at 2026-11-05T20:00:00Z). `/hike` and `/hike/` are the same file.
- States: **published** is the folder exactly as published (no club service, so both signup forms are disabled and the `/hike/` sample invitation and trail map show). **service-fixture** (`/` and `/hike/`) removes the "no club service" marker as `static-site-qa.cjs` does and answers `GET /api/community` from a synthetic fixture (one event "Synthetic keyboard walk", the route ideas from `community.json`), so the live signup fields, the RSVP button and the RSVP dialog exist. Nothing is submitted: the run saw 0 non-GET requests and 0 requests to any other host. The sample RSVP was submitted once in the browser with a synthetic name and address and sends nothing (`community.js:136`).
- Per page the collector reads the DOM and Chrome's accessibility tree (CDP `Accessibility.getFullAXTree`; axe is not used), then presses Tab from the top until focus leaves or wraps (cap 900). Every stop is checked for being covered (`elementFromPoint` at 5 points of its box); the first stop of each control kind is screenshotted focused and blurred and the pixels are compared (no difference = no visible focus indicator). Dialogs are opened with Enter, walked with Tab and closed with Escape. The dialogs were also run in a 360 px high viewport, where sticky buttons overlap most.
- 2.5.8: every enabled link, button, input, select and summary is measured; under 24x24 CSS px passes only if it is inline in a sentence, or a 24 px circle on its centre touches no other target (or other undersized target's circle). Checkbox targets use their label box.
- Detector controls (404 page, `selfChecks` in the JSON, run on every collection): a default focus ring is seen; the same ring with `outline:none` is not; a fixed overlay is reported as covering; two adjacent 10 px targets fail 2.5.8; one isolated 10 px target passes by spacing.
- Limits: Chromium only (no Firefox, Safari, screen reader or physical device); the focus indicator test sees that something changed, not whether it meets a contrast ratio; widths 390 and 1440 only, plus the 360 px high dialog runs (no 200% zoom or 320 px reflow run); hover-only and drag-only behaviour is not exercised; pages are the published routes only.

## Pass list per criterion

### 1.1.1 Non-text content
- `/`: 108 `img`, every one has a non-empty `alt` and none is a file name (105 card photos from `shop.js:11`, which adds "(illustration)" to drawn pictures; the logo; Michael's photo). 0 `svg`, 0 `role=img`.
- `/hike/`: 3 `img` (logo, Michael `hass/templates/hike/index.html:19`, Point Buchon photo `community.js:31`) all with `alt`. 7 `svg`: 6 are inside `aria-hidden` (4 control icons `trail-explorer.js:8`, compass `:32`, map canvas `:31`); 1 is `role=img` with an `aria-label` (elevation chart, `:37`). The aerial image is inside the hidden canvas; its text equivalent is the stage's `role=region` label, `#trail-map-help`, the stats and the chart label.
- `/404.html`: 1 `img` (logo) with `alt`.
- Cited, not repeated: `storefront-mockup/static-site-qa.cjs:71-72` asserts every `img` has alt text. Known pass control, run on this tree: `static-site-qa.cjs` printed `imagesWithoutAlt:0` for `/`, `/hike`, `/hike/` and `/404.html`, matching this collector's 0 `img` without `alt` (108, 3, 3, 1 images).

### 1.3.1 Info and relationships
- Headings, no skipped level, exactly one `h1` per page: `/` 110 headings (h1, h2, 105 card h3, then h2 sections); `/hike/` 10 in published state (h1, h2, h3, h4, h3, h3, h2, h3, h3, h2) and 9 in service-fixture; `/404.html` 1 (h1). Cited: `static-site-qa.cjs:94-95` checks `/hike` heading order.
- Landmarks on every page: 1 banner, 1 main, 1 contentinfo, 1 navigation named "Main". Named regions: `/` 1 (newsletter), `/hike/` 4 (club, journal, trail explorer, map stage), plus the named sample RSVP form (`community.js:51`).
- Form labels: 0 unlabelled controls. Every control has a `<label>` (for or wrapping): `/` 4 (search, producer select, newsletter email, checkbox), `/hike/` 5 in published state (slider, sample RSVP name, group size, email, trail-list email) and 2 in service-fixture, RSVP dialog 3. 0 duplicate ids, 0 `for`/`aria-labelledby`/`aria-describedby` pointing nowhere. Placeholder is never the only label.
- Related fields in the dialogs sit under a dialog name: Privacy (`aria-labelledby` the h2), RSVP ("Join the next hike."), map (`aria-label` "Point Buchon map and elevation").

### 2.1.1 Keyboard and 2.4.3 Focus order
- Tab walk, every enabled visible control reached, 0 positive `tabindex`, 0 upward jumps over 240 px, focus left the page after the last control (no trap): `/` 227 stops (231 in service-fixture; the 3 other controls are disabled by design, see below), `/hike/` 32, `/404.html` 13. The walk loads all 105 cards.
- Skip links work on all three routes: Enter on "Skip to ..." then Tab lands inside the target (`#market`, `#hikes`, `#main`).
- Catalog filters: Space on "Dairy & cheese" sets `aria-pressed=true`, the count reads "20 selections", focus stays on the button. Card details: Enter on "Meet the maker" opens the `details`; the next Tab reaches "Visit Taco Works".
- Trail map: stage `+`, `-`, arrows, Home (zoom 1.00 to 1.60 and back, view moves); Aerial/Topo and Zoom in/Fit with Enter; elevation slider ArrowRight changes the readout (`trail-explorer.js:131`, `:114`).
- Enlarged map dialog: Enter on "Enlarge map" puts focus on "Close map", 10 stops in a sensible order, Escape closes and focus returns to "Enlarge map" (`:127`). RSVP dialog (service-fixture): Close, name, email, group size, Save; Escape returns focus to "RSVP to this hike". Privacy dialog: Close only; Escape returns to "Privacy". Cited, not repeated: `static-site-qa.cjs:245-282` (backdrop, padding, Close and Escape behaviour).
- Sample RSVP: Enter in the email field shows "That's how the RSVP will work. No details were saved or sent." and moves focus to that status (`community.js:136`).
- Signup forms (newsletter, hike updates): disabled up front in the published state with a status sentence (`community.js:177`); not focusable by design. In service-fixture all their fields and buttons were stops.

### 2.4.7 Focus visible
- Every kind of control, compared pixel for pixel focused versus blurred, shows an indicator: 11 kinds on `/` (14 in service-fixture), 13 on `/hike/` (11 in service-fixture), 5 on `/404.html`, plus the dialog buttons and fields. CSS: `style.css:1` (links, buttons, inputs, `select:focus-visible` at `:3`), `:45` (summary), `trail-explorer.css:14` (map controls, stage, close). No `outline:none` rule exists in the three style sheets. Detector control: see `selfChecks`.

### 2.4.11 Focus not obscured (minimum)
- No focus stop on any page or dialog was entirely hidden: 0 of 227, 32 and 13 page stops, and 0 of 10 (map) and 4 (RSVP) dialog stops at 390x844, 1440x900 and 360 px high, except the partial case N1.
- Sticky or fixed elements found: only `dialog .close` (`style.css:12`) and `.trail-map-close` (`trail-explorer.css:76`) while a dialog is open; none on any page. **Fixed toast:** `#toast{position:fixed;display:none}` exists in `style.css:1`, but no markup or script creates `#toast` (0 in every route and state), so it never shows and nothing can sit under it. N/A at this SHA.

### 2.5.8 Target size (minimum)
- 0 failures. `/`: 227 targets (231 in service-fixture), smallest non-inline "Link to this" 62x31 (`.text-link` has `min-height:44px`, `style.css:1`). `/hike/`: 31 targets, 5 undersized links are inline in the photo credit and map caption sentences (exempt). `/404.html`: 13, smallest 74x31 and Privacy 39x44.
- One link passes by the spacing exception: `a.text-link` "Next hike: ..." 419x16 at 1440 in service-fixture (`style.css:66`).
- Open dialogs: Close 44x44, "Close map" 115x44, RSVP fields 304x48 (390) and 586x48 (1440).

### 4.1.2 Name, role and value
- Every interactive element has a role and a name: 230 on `/`, 35 on `/hike/`, 13 on `/404.html` (published). 0 empty names, 0 focusable elements inside `aria-hidden`, 0 interactive elements missing from the accessibility tree. Roles seen: link, button, searchbox, combobox, slider, disclosure (`summary`), region (map stage).
- Values and states: `aria-pressed` on 10 filter buttons and Aerial/Topo, true after activation; `details` expanded after Enter; slider `aria-valuetext` set (`trail-explorer.js:109`) and follows the arrow keys; the zoom buttons' `disabled` state is exposed (see F2 for focus). Dialogs named as above; Close buttons are named "Close details" and "Close map x". Live regions: `#catalog-count` polite, `#upcoming-hikes` polite, `.form-status` `role=status`.
- Zero JavaScript errors on every page and state.
